# 验证记录

验证日期：2026-10-24；本机 Apple Silicon，macOS 26.5.2，部署目标 macOS 14+。

## 已通过

- 15 项 XCTest，包括模板的 10 项布局／状态测试与 5 项文件存储／拖放格式测试。
- 普通文件复制、内容去重、同名不同内容隔离、原文件保留、源文件删除后托管副本可读、manifest 重启恢复、已读状态恢复。
- 缺失文件和文件夹的错误报告；损坏清单不被静默覆盖。
- NSURL 写入和读回 NSPasteboard 的原生文件 URL 格式；文件拖动检测区分新拖动与旧 pasteboard 残留。
- Swift Debug 与 Release 构建；本机 ad-hoc 签名校验。
- 真实 SwiftUI 视图的顶部浅色、底部深色、左侧迷你渲染检查。修复了 NSImageView 固有尺寸导致缩略图超出区域的问题。
- 实机通过原生文件选择器批量导入 Markdown、PNG、PDF，卡片数量和缩略图正确。三份原文件与托管副本 SHA-256 均一致。
- 实机点击 PDF 的“预览”：Quick Look 正常显示文档文字；预览窗口在挂卡栏上方。截图已保存。
- 实机点击 PNG 的“打开”：系统“预览”打开的是 Application Support 中的托管副本。
- 标记 PDF 已读后终止并重新启动打包应用：4 份文件及 PDF 已读状态恢复。
- 用户亲自完成 Finder → 稍后阅读、卡片缩略图 → Finder 双向拖放，于本轮回复“拖入、拖出都成功”。自动操作工具的跨窗口拖动未形成可确认的拖放事件，因此此项依据用户实测，不冒称自动化端到端通过。
- 发现启动／重新打开后未固定的文件架过快消失，新增重新打开即展开，并保留 10 秒操作时间；已回补模板。启动后的实际窗口已验证。
